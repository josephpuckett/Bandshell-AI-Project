Bandshell Calendar · User guide

Putting events on other people's calendars, without the copy-paste

This app teaches a small robot how to fill in one website's event form. You show it once, you check its work, and after that it can do that website for you in a couple of minutes per event.

🛡️ Nothing is ever posted by itself. The robot fills the form; you look at it and press submit on the calendar site yourself.

The big idea

Three things happen, in this order. Only the first one is slow.

1

You demonstrate (once per website)

Open a website and click Set up this website. An AI opens the real form in a browser and starts filling it in. You watch, and step in when it needs you (a login, a captcha, a field it got wrong).

2

You approve

If the form looks right, click Approve. If not, click Reject and say what's wrong — the AI tries again.

3

You reuse it forever

The app writes down what worked as a routine for that website. Next time you just pick an event, press run, check the filled form, and submit. No AI, no waiting.

Think of it like this

You're not teaching the app what your events are — you already know that. You're teaching it where the boxes are on one particular website. That knowledge is what gets saved.

Before you start

A five-minute check that saves an hour later.

  • The link to the app and a username and password from whoever set it up. Your browser will remember them after the first prompt.
  • The event details you'd type by hand anyway: title, date and times, a short blurb and a longer description, ticket price, and a link to an image.
  • The calendar website's own login, if it needs one. Sometimes you'll have to type it into the live page yourself — that's normal and expected.
  • An image link that anyone can open. If you use Google Drive, right-click the file → Share → Anyone with the link → Viewer. Otherwise the calendar site will quietly reject it.
  • A modern browser (Chrome, Edge, Firefox, Safari) and permission to leave the tab open while the AI works.
Don't do this on your phone

The live page needs mouse clicks and a keyboard. A laptop or desktop is much easier.

The four steps

You do all of this in the app's own screens. Buttons are named exactly as they appear.

1

Create the event 2–3 minutes

  • Click + New Event.
  • Fill in the title, dates and times, a short summary, a long description, and the image link.
  • Leave the contact fields and the website address blank unless this event is different from usual — blank means "use the defaults".
  • Click Save. The event now appears in the Events list.

The venue, cost, categories and timezone aren't asked here: they live in ⚙️ Settings because they're nearly always the same.

2

Add the website 1 minute

  • Switch to the Websites view and click + Website.
  • Give it a name you'll recognise (e.g. "Downtown Arts Calendar") and paste the address of the page where events get submitted.
  • Click Save. The website shows a grey Not set up badge.

You do this once per calendar website — not once per event.

3

Set the website up with the AI 5–15 minutes, one time only

This is the only part that needs your attention. Expect waiting, and expect to help.

  • Open the website and click Set up this website, picking which event to use as the example.
  • Watch the Live page panel. The AI is driving a real browser: it clicks, types, opens menus.
  • If it asks for a login, or a captcha appears, or a date picker pops up — jump in. Click and type directly in the live page (details below).
  • When the form is filled correctly, click Approve.
  • If it's wrong, click Reject and write a short note ("the description goes in the second box", "wrong date format"). The AI reads it and tries again.
  • After you approve, the app writes the routine and runs it once so you can see it work. Approve that, and the website badge turns Ready.
Be specific when you reject

"Wrong" and "try again" waste a round trip. "The price goes in the free-ticket box, leave the paid box empty" gets it right the first time.

4

Review and submit 2–4 minutes

  • Pick the event you want to publish to this website and press run.
  • The routine fills the real form. Read it in the live page — title, dates, description, image, price.
  • Fix anything by clicking into the field and typing.
  • Press the website's own submit button inside the live page. You post it, not the app.
  • Click ✓ Done to close the page and finish.
The one rule

Check before you submit. The app will happily fill a form with a typo you gave it.

Next time (the actual payoff)

Roughly two minutes per event, per website, with no AI involved.

  1. Create the new event.
  2. Open the website (badge Ready) and run it with that event.
  3. Check the filled form in the live page, submit it, click ✓ Done.

If a website's badge says Needs attention or Stale, something about the site or the settings changed. Re-run the one-time setup for that website — it's usually quicker the second time.

The live page, explained

It looks like a website, but it's a live picture of a browser running on the server.

You'll seeWhat it means
A grey box saying "No live page right now" Nothing is running yet. It appears once setup starts or a routine runs.
Hovering text like "It's your turn — click & type" The app has paused and is waiting for you. Your clicks and typing are sent to the real browser.
Frames that update slowly (a few per second) Normal — it's a stream of pictures, not a video, to keep it light.
Scrolling works, but select/copy doesn't By design: it's made of images, so there's no text to select.
A tip about using the keyboard instead A date picker or dropdown is open. Those are drawn by the browser itself and can't be pictured — type the date and press Enter/Tab instead.
Paste, the useful trick

Copy text from anywhere, click the field in the live page, and press Ctrl+V (⌘+V on a Mac). It's the fastest way to drop a long description in.

When something looks wrong

Click a question to open the answer.

The live page is blank or frozen

Give it a few seconds, then refresh the browser tab. The view reconnects on its own; a refresh is harmless — it doesn't stop the AI or lose the form.

It keeps asking me to log in

That's the app's own password (the browser should offer to remember it, and it usually does after the first time). If it's a website login that keeps coming back, the site may be signing the browser out — reject the attempt and mention it in the note; the AI can log in again during the next try.

A badge says "Stale"

The shared defaults (venue, location, cost, categories) changed after this website was set up, so the saved routine might not match the live form any more. Re-run the one-time setup for that website to refresh it.

The setup failed, or the AI did something strange

Click Reject and describe the problem in plain words. It retries with your note. If it fails the same way twice, it's usually the website (a new captcha, a changed layout) rather than you.

I submitted the wrong thing

Fix it on the calendar website itself — the app doesn't keep a copy of what was submitted, and it can't edit an entry for you. For Eventbrite, edit the draft before publishing.

The whole app says "This server is shutting down"

The server switches itself off after a long period of inactivity to save money. Nothing is lost — but you'll need whoever runs it to start it again, then reopen the link.

Everything is greyed out

The app only lets you click while it's your turn. Buttons that belong to a later step stay disabled until the current one finishes.

I clicked "Done" and now I can't see the form

Done closes the page — it means "I'm finished with this one". To see it again, run the routine for that event once more. Nothing was submitted twice.

Good habits

Keep the tab open

During setup, closing the tab stops you watching — and you're the one who has to notice problems.

One event per run

Routines fill one form for one event. Finish and click Done before starting the next.

Say what's wrong

A short, specific note on a rejection is worth ten silent retries.

Trust your eyes

The app has no idea whether your event description is good. That part is still you.

For whoever runs the server

Skip this unless you're the person maintaining the machine.

The app is installed on a Debian/Ubuntu server

Everything is set up by deploy/install.sh (nginx with a login, the app itself, and a startup service). To update after pulling new code, re-run it:

sudo bash deploy/install.sh --auth-user you --nginx-port 8080

To hand it your secrets instead of typing them in, download the env file and the Google key first and add --env-file ~/bandshell.env --google-key ~/key.json. It's safe to re-run; it refreshes the code, the settings and the service.

How do I change the app's password?

sudo bash deploy/install.sh --auth-pass 'a-new-one' — or directly sudo htpasswd /etc/nginx/bandshell.htpasswd youruser, which takes effect immediately. A plain re-run never changes an existing password.

The public address (ngrok)

If NGROK_URL and NGROK_AUTHTOKEN are set in the env file, a tunnel runs as ngrok.service and forwards the public URL to nginx, so the login still applies. Check it with systemctl status ngrok, watch it with journalctl -u ngrok -f; the first visit in a browser may show ngrok's own warning page once — click through it.

Checking that the app can see its keys

curl -s http://127.0.0.1:8000/api/health — shows booleans only (never secrets). Secrets live in /etc/bandshell/bandshell.env, one KEY=VALUE per line, and the service must be restarted after editing.

It powers itself off when idle

That's AUTO_SHUTDOWN_MINUTES (off by default). AUTO_SHUTDOWN_DRY_RUN=1 logs the decision without switching off, and curl -s http://127.0.0.1:8000/api/activity shows how idle it is, whether work is in flight, and when it would stop. A stopped machine has to be started again from your cloud console.

Where the logs are

journalctl -u bandshell -f for the app, and logs/llm_usage.jsonl in the project for one line per AI call.
